# Salesforce チーム開発ガイド (SF TeamFlow)

複数人で Salesforce を安全に開発するための進め方です。**初めての方はこの順番で読めば大丈夫です。**
（このファイルは拡張の「チーム開発ガイドを開く」コマンドでも表示されます）

## 全体像 — 3つの環境とブランチ

```
   開発者A ─┐
   開発者B ─┼─▶ develop ブランチ ─▶ 統合(integration) Sandbox
   開発者C ─┘        │
                     ▼
              release/* ブランチ ─▶ ステージング(staging) Sandbox  … 受入テスト
                     │
                     ▼
                  main ブランチ ─▶ 本番(production)            … お客様が使う環境
```

| 環境 | 役割 | ブランチ | 誰が触る |
|------|------|----------|----------|
| **開発 (dev/scratch)** | 個人が自由に試す | `feature/*` | 各開発者 |
| **統合 (integration)** | 全員の変更を合流して確認 | `develop` | 自動デプロイ |
| **ステージング (staging)** | 本番同等で受入テスト | `release/*` | QA・リーダー |
| **本番 (production)** | お客様が使う | `main` | リリース担当のみ |

> この対応は `sf-teamflow.json` に書いて全員で共有します。SF TeamFlow が現在のブランチから
> 自動で「どの環境・どのOrgか」を判断します。

## 日々の流れ (開発者)

1. **作業ブランチを作る** … 「ブランチ」行をクリック → `feature/取引先検索` のように作成
   （1機能=1ブランチ。他の人の作業と混ざりません）
2. **自分の開発Orgで作る** … スクラッチOrg or 個人Sandbox にソースを反映(push)して動作確認
3. **こまめに保存してバックアップ** … 「保存してバックアップ」(commit + push)。1日数回でOK
4. **Pull Request を出す** … GitHub 上で `develop` へ PR。CI が自動で検証
5. **レビュー → マージ** … 仲間がレビュー。マージされると統合Sandboxへ自動デプロイ

## なぜ Git / GitHub なのか（バックアップとバージョン管理）

- **バックアップ**: ローカルだけだとPC故障で消えます。push すれば GitHub に安全に保管されます。
- **バージョン管理**: 「いつ・誰が・何を変えたか」が全部残る。壊れても前の状態に戻せます。
- **共同作業**: 同じ組織を複数人で直接いじると上書き事故が起きます。Git なら各自のブランチで作業し、
  PR でぶつかり（コンフリクト）を安全に解消できます。

### 複数人開発のおすすめルール
- `main` / `develop` には**直接 push しない**（必ず PR 経由）。GitHub の Branch protection を設定。
- PR は小さく・こまめに。レビューしやすく、コンフリクトも減ります。
- コミットメッセージは「何をしたか」を日本語で具体的に。
- 本番反映は**リリース担当者だけ**が `main` へマージ。SF TeamFlow は本番デプロイ前に必ず確認します。

### Branch protection の推奨設定 (GitHub)
- `main`, `develop` を保護
- PR レビュー必須（1名以上の承認）
- ステータスチェック必須（`SF Validate (PR)` のパス）
- 管理者にも適用

## スクラッチOrg の活用

スクラッチOrg = 使い捨ての開発用Org。**個人の実験に最適**です。

- 「スクラッチOrgを作成」で数分で新しいOrgが手に入る（最大30日）
- ローカルのソースを「Orgに反映 (push)」して試す
- Org側で設定変更したら「Orgから取り込み (pull)」でローカルに戻す
- 終わったら「スクラッチOrgを削除」で片付け（数に上限があるため）

> 要 Dev Hub（スクラッチ作成元のOrg）。本番/開発Edition組織で Dev Hub を有効化しておきます。

## メタデータの取得 (既存組織から始める)

すでにある組織から開発を始める場合:
1. 「メタデータを取得」で Apexクラス・オブジェクト等を選んでローカルに取り込む
2. または `manifest/package.xml` を用意して「manifestで取得」
3. 取り込んだら Git に保存してチームと共有

## 困ったときは
- **デプロイできない / セッション切れ** … Orgを開き直して再ログイン → 「Org一覧を更新」
- **同期でコンフリクト** … 落ち着いて該当ファイルを開き、どちらの変更を残すか決めて保存
- **本番に出していいか不安** … まず「Git差分を検証」(デプロイなし) で安全確認
